# MAC Pattern Classifier

## 1. 프로젝트 개요
본 프로젝트는 MAC(Multiply-Accumulate) 연산을 이용하여 입력 패턴이 `Cross`인지 `X`인지 판별하는 시뮬레이터를 구현한 것이다.  
패턴과 필터 데이터를 JSON 파일로 관리하며, 단일 입력 판별 / 전체 배치 테스트 / 성능 분석 기능을 제공한다.

## 3. 구현 요약
### 3-1. 모듈 구성
- mac_engine.py : MAC 연산 수행
- pattern_manager.py : 패턴/필터 관련 처리
- data_handler.py : JSON 로드, 저장, 검증
- performance_analyzer.py : 실행 시간 측정 및 성능 분석
- simulator.py : 메뉴별 실행 흐름 제어
- main.py : 프로그램 시작점

### 3-2. 라벨 정규화 방식
- "Cross" → "cross"
- "CROSS" → "cross"
- "X" → "x"

### 3-3. MAC 연산 구현 개요
- 각 입력 패턴은 동일한 크기의 cross 필터와 x 필터에 대해 각각 MAC 연산을 수행한다.
- 이후 두 점수를 비교하여 더 높은 점수를 얻은 클래스로 판정한다.

예:
cross_score > x_score 이면 cross
x_score > cross_score 이면 x
3-4. 동점 처리 정책 (epsilon)
부동소수점 계산 오차 또는 거의 동일한 점수 차이를 고려하여 epsilon 기준을 적용하였다.

예:

abs(cross_score - x_score) < epsilon 이면 동점 또는 애매한 결과로 간주
그 외에는 더 높은 점수의 클래스로 판정
이 정책은 미세한 오차 때문에 결과가 불안정하게 바뀌는 문제를 줄이기 위해 사용하였다.

### 3-4. 동점 처리 정책 (epsilon)

### 4-3. FAIL 케이스 원인 분석
- 실패 케이스가 존재한다면, 각 케이스에 대해 원인을 분석하였다.
- 예시 분석 항목:
라벨 표기 불일치 (Cross, cross, X, x)
JSON 스키마 차이 (patterns[pkey] 구조 변경)
필터 크기와 패턴 크기 불일치
부동소수점 오차
비교 정책 미비 (동점 처리 없음)

### 4-4. FAIL이 0개인 경우
- 본 프로젝트에서는 라벨 정규화, JSON 구조 검증, 크기 검증, epsilon 기반 비교 정책을 반영하여 테스트 실패를 최소화하였다.
- 그 결과, 최종 배치 테스트에서 0 FAIL을 달성하였다.

- 0 FAIL의 주요 이유는 다음과 같다.
- 라벨 정규화를 통해 문자열 표기 차이를 제거하였다.
- validate_matching()을 통해 필터와 패턴의 크기 일치 여부를 사전에 검증하였다.
- extract_size() 수정으로 size_3, size_3_1 형식을 모두 안정적으로 처리하였다.
- judge()에 epsilon 비교 정책을 적용하여 미세한 점수 차이에 의한 오판정을 줄였다.

## 5. 성능 분석
### 5-1. 측정 대상
성능 분석은 서로 다른 크기의 패턴에 대해 MAC 연산 수행 시간을 측정하는 방식으로 진행하였다.

측정한 패턴 크기:
- 3x3
- 5x5
- 13x13
- 25x25
### 5-2. 성능 측정 결과 표
### 5-3. 성능 표 해석
- 패턴 크기가 커질수록 연산에 필요한 원소 수가 증가하므로 실행 시간도 함께 증가하는 경향을 보였다.
- 특히 2차원 패턴의 한 변 길이를 N이라고 할 때 전체 원소 수는 N^2개이므로, MAC 연산은 각 원소를 한 번씩 순회하면서 누적 계산을 수행하게 된다.
- 따라서 입력 크기가 증가할수록 수행 시간은 대체로 원소 수 증가에 비례하여 증가한다.

### 5-4. 시간 복잡도 분석
- MAC 연산은 N x N 크기의 입력 패턴과 필터를 원소 단위로 곱하고 모두 더하는 방식이다.
즉,
곱셈 연산: N^2회
덧셈 연산: N^2회에 비례
따라서 전체 시간 복잡도는 다음과 같다.

[
O(N^2)
]

- 근거
- 입력 패턴의 모든 칸을 정확히 한 번씩 방문해야 하므로, 연산량은 입력 크기의 제곱에 비례한다.
- 실제 측정 결과에서도 3x3 → 5x5 → 13x13 → 25x25로 갈수록 실행 시간이 증가하여 이론적인 시간 복잡도와 일치하는 경향을 확인할 수 있었다.
